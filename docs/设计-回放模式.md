# 回放模式（Replay Mode）设计文档

本文档阐述 BT Web Studio 中「回放模式」的业务目标、信息结构、交互流程与技术架构，与 [设计-编排模式.md](设计-编排模式.md)、[设计-调试模式.md](设计-调试模式.md) 并列，作为三模式设计体系的一部分。

## 1. 目标与范围

- **目标**：基于事件日志的时间轴回放，支持时光穿梭、书签跳转、轨道筛选与快照导出，帮助用户离线分析行为树执行轨迹。
- **范围**：
  - 回放会话加载（在线调试录制缓冲、离线日志导入 JSON/MessagePack）。
  - 时间轴驱动与播放控制（播放/暂停、快进/后退、跳转、速度调节）。
  - 分轨道呈现（状态轨、日志轨、断点轨、黑板轨）。
  - 画布与时间轴双向联动（点击轨道事件高亮节点，反之亦然）。
  - 书签与标注、回放快照导出。

不在本阶段范围（但保留扩展位）：多次运行对齐与比较、版本差异叠加。

## 2. 角色与典型场景

- **调试工程师**：调试结束后，从录制缓冲进入回放，逐帧分析断点命中、状态切换与黑板变化。
- **测试/QA**：导入离线日志文件，复现异常执行路径，定位问题节点。
- **架构师**：对比多次运行轨迹，评估行为树结构与执行效率。

## 3. 信息结构与核心概念

- **Timeline（时间轴）**：start、end、tracks、markers；表示一次回放会话的时间范围与轨道集合。
- **Track（轨道）**：State | Log | Breakpoint | Blackboard；按类型聚合事件。
- **Segment（片段）**：t0、t1、value；表示轨道上的一段数据（如状态、日志文本、变量变化）。
- **Marker（标记）**：ts、label；书签或关键帧，用于快速跳转。
- **Timeline Driver（时间轴驱动）**：维护 virtualTs，根据播放速度推进，将 virtualTs 投影为「合成运行态」推送到画布与右侧面板。

Glossary：
- Replay Mode：回放模式，以时间为中心，仅呈现历史状态，不修改结构。
- ExecutionEvent：统一事件格式，含 ts、kind、payload。
- 合成运行态：由 virtualTs 投影得到的节点状态与黑板快照，用于画布渲染。

## 4. 用户流程（高层）

1) 进入回放模式：从调试模式「断开/停止」后携带录制缓冲进入，或从顶部「加载」导入离线日志。
2) 时间轴控制：播放/暂停、上一事件/下一事件、拖拽游标、跳转书签。
3) 轨道筛选：显示/隐藏状态轨、日志轨、断点轨、黑板变量轨。
4) 画布联动：点击轨道事件 → 高亮对应节点；点击画布节点 → 定位到该节点在时间轴上的事件。
5) 导出：为关键时刻加书签，导出回放片段（含事件与黑板快照）。

## 5. 布局与区块设计

### 5.1 整体布局

```
[顶部：模式切换 + 加载 + 预览 + 设置 + 帮助]
[左侧：书签/事件列表] [中央：回放画布] [右侧：轨道筛选 + 该帧快照]
[底部：时间轴控制器]
```

- **顶部**：模式切换、加载（仅回放）、预览、设置、帮助（见 [设计-顶部工具栏.md](设计-顶部工具栏.md)）。
- **左侧**：书签列表（异常帧、断点命中、版本切换点）、事件列表与搜索。
- **中央**：回放画布，按 virtualTs 渲染节点状态与路径轨迹；禁用节点结构编辑。
- **右侧**：轨道筛选（显示/隐藏各轨）、该帧变量快照、端口快照、日志。
- **底部**：时间轴（播放控制、缩放、轨道可见性、游标拖拽、区间圈选）。

### 5.2 时间轴控制区

- **播放控制**：播放/暂停、上一事件/下一事件、跳转书签。
- **缩放控制**：时窗缩放（滚轮 + Ctrl）、双击智能缩放到选中事件簇。
- **选择同步**：画布与时间轴联动（点击轨道事件 → 高亮节点；反之亦然）。

### 5.3 轨道类型

| 轨道类型 | 说明 | 可视化 |
|----------|------|--------|
| 节点状态轨 | 按节点类型或选中节点显示状态切换片段 | 状态色块（IDLE/RUNNING/SUCCESS/FAILURE/SKIPPED） |
| 日志轨 | 按级别着色、点击展开详情 | 级别色 + 文本摘要 |
| 断点轨 | 命中点显示标记 | 标记点 + 悬浮显示节点与计数 |
| 黑板轨 | 选择关键变量，绘制变更点或区间 | 旧/新值标注 |

## 6. 数据模型（前端）

### 6.1 回放与时间轴

```ts
interface Timeline {
  start: number
  end: number
  tracks: Track[]
  markers: Marker[]
}

interface Track<T = any> {
  id: string
  type: 'State' | 'Log' | 'Breakpoint' | 'Blackboard'
  segments: Segment<T>[]
}

interface Segment<T = any> {
  t0: number
  t1: number
  value: T
}

interface Marker {
  id: string
  ts: number
  label?: string
}
```

### 6.2 ReplayModeSlice（Zustand）

```ts
interface ReplayModeSlice {
  replaySession: ReplaySession | null
  timelinePosition: number      // virtualTs
  playbackSpeed: number
  isPlaying: boolean
  loopEnabled: boolean
  selectedEventTypes: string[]
  // actions
  loadSession(source: 'buffer' | File): void
  play(): void
  pause(): void
  seek(ts: number): void
  setPlaybackSpeed(speed: number): void
  addMarker(ts: number, label?: string): void
  jumpToMarker(markerId: string): void

```

### 6.3 事件格式（与调试模式统一）

```ts
type EventKind = 'StateChange' | 'Breakpoint' | 'Hook' | 'Log' | 'Blackboard'

interface ExecutionEvent {
  ts: number
  kind: EventKind
  payload: any
}
```

## 7. 回放系统设计

### 7.1 事件来源

- **在线调试录制缓冲**：调试期间事件落入缓冲，Stop/Pause 后进入回放。
- **离线日志导入**：JSON/MessagePack 格式，与 ExecutionEvent 统一，经 Schema 校验后加载。

### 7.2 时间轴驱动（Timeline Driver）

- 维护 `virtualTs`，根据播放速度推进。
- 对 ExecutionEvent 做时序索引，支持 O(log n) 范围查询。
- 将 virtualTs 投影为「合成运行态」（NodeRuntimeState、BlackboardSnapshot），推送到画布与右侧面板。

### 7.3 快照与书签

- 支持为关键时刻（断点、错误、用户标注）加书签。
- 可导出回放片段（含事件与黑板快照），便于分享与问题复现。

### 7.4 性能策略

- 轨道虚拟化：仅渲染可视范围，事件密度高时采样/合并。
- 画布：只对视口内节点做状态绘制；大规模树启用节点层级折叠。
- 状态批处理：例如 16ms 合并一次，避免高频重绘。

## 8. 技术架构

- **React + ReactFlow**：回放画布复用编排画布结构，叠加状态 overlay，禁用编辑交互。
- **Zustand**：`replayModeState.ts`、`timelineState.ts`，与 `modeSlice` 联动。
- **时间轴组件**：`timeline-controller.tsx`、`interactive-timeline.tsx`、`bottom-timeline.tsx`。
- **布局**：`replay-layout.tsx`，与 `mode-aware-layout` 集成。

## 9. 与编排/调试模式的关系

- **编排 → 回放**：需先有行为树结构；回放仅展示状态，不修改结构。
- **调试 → 回放**：断开或停止后，携带录制缓冲进入回放；或从历史日志进入。
- **回放 → 编排**：结束回放或返回编辑；也可回放 → 调试 再连。

## 11. 验收标准

- 加载回放后，时间轴可正确显示事件范围与轨道。
- 播放/暂停/跳转反馈 < 100ms。
- 画布与时间轴双向联动无误。
- 轨道虚拟化下，大于 10k 事件仍可流畅滚动。
- 导出快照包含完整事件与黑板状态，可被重新加载。

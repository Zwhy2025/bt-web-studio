# 三模式架构

## 1. 目标与范围

- 目标：将编辑、在线调试、离线回放拆分为独立工作模式，降低认知负担。
- 范围：模式状态机、模式边界、模式切换副作用。
- 非目标：具体组件 API 和协议字段细节。

## 2. 依赖与入口

- 模式状态：`src/core/store/workflowModeState.ts`
- 顶层布局：`src/components/layout/mode-aware-layout.tsx`
- 三模式页面：
  - `src/components/layout/composer-layout.tsx`
  - `src/components/layout/debug-layout.tsx`
  - `src/components/layout/replay-layout.tsx`

## 3. 核心概念与状态机

### 3.1 模式定义

- `composer`：结构编辑与校验。
- `debug`：实时调试与会话控制。
- `replay`：时间轴回放与分析。

### 3.2 状态切换规则

```text
composer -> debug -> replay
composer <- debug <- replay
```

- `composer -> debug`：加载当前树并冻结结构写操作。
- `debug -> replay`：保留录制事件，切换到离线时间轴。
- `replay -> composer`：退出回放，恢复结构编辑。

## 4. 关键流程

1. 用户触发模式切换。
2. `workflowModeState` 校验目标模式可达性。
3. 触发模式副作用（启停订阅、重置局部 UI 状态）。
4. `mode-aware-layout` 切换主视图。

## 5. 异常与边界

- 连接失败时不得强制进入 `debug` 运行态。
- `replay` 无数据时只显示加载入口，不渲染空回放流程。
- 模式切换期间禁止重复切换，防止状态抖动。

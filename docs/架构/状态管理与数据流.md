# 状态管理与数据流

## 1. 目标与范围

- 目标：明确 Zustand 各 slice 职责，避免状态重复和跨层耦合。
- 范围：`src/core/store/*`，以及与画布、调试、回放相关的数据流。

## 2. 依赖与入口

- Store 组装：`src/core/store/behavior-tree-store.ts`
- 类型定义：`src/core/store/behavior-tree-types.ts`
- 关键 slices：
  - 会话：`sessionState.ts`
  - 树结构：`treeState.ts`
  - 模式：`workflowModeState.ts`
  - 编排：`composerModeState.ts`
  - 调试：`debugModeState.ts`、`debuggerState.ts`
  - 回放：`replayModeState.ts`、`timelineState.ts`
  - 通用 UI：`uiState.ts`、`blackboardState.ts`

## 3. 状态分层

| 层级 | 对应 slice | 说明 |
|---|---|---|
| 全局会话层 | `sessionState` | 当前工程、tab、会话基础信息 |
| 结构层 | `treeState` | `nodes` / `edges` 与导入导出 |
| 模式层 | `workflowModeState` | 三模式切换与过渡状态 |
| 模式特化层 | `composer/debug/replay*` | 各模式独有状态与动作 |
| UI 辅助层 | `uiState` | 面板显隐、选择状态等 |

## 4. 关键数据流

### 4.1 编排流

`节点操作 -> treeState -> composerModeState -> Canvas`

### 4.2 调试流

`WebSocket 消息 -> debuggerState/debugModeState -> nodeState/blackboard -> DebugCanvas`

### 4.3 回放流

`事件数据 -> replayModeState/timelineState -> 当前时间片状态 -> ReplayCanvas`

## 5. 异常与边界

- 禁止在 `debug/replay` 写入结构层（`nodes`/`edges`）的持久变更。
- 高频事件必须批处理，避免全量重渲染。
- 重连或切换会话后要重置与会话绑定的 transient 状态。

## 6. 与其他模块关系

- 调试通信：`src/core/debugger/*`
- 结构解析：`src/core/bt/*`
- 布局算法：`src/core/layout/*`

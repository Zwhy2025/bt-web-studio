# 文档编写规范

## 1. 目标

确保文档可维护、可检索、可与代码同步演进。

## 2. 文件组织规范

- 架构文档放 `docs/架构/`
- 模式文档放 `docs/模式/`
- 共享组件文档放 `docs/组件/`
- 协议文档放 `docs/协议/`
- 代码子模块文档放 `docs/模块/`
- 研发辅助文档放 `docs/研发/`

## 3. 命名规范

- 继续使用中文文件名，目录分层表达语义。
- 协议文档使用 `Groot2-*.md` 前缀。
- 模块文档使用 `core-*` / `components-*` / `hooks` 风格。

## 4. 每篇文档的最小结构

1. 目标与范围
2. 依赖与入口（代码路径）
3. 核心概念/数据结构
4. 关键流程
5. 异常与边界
6. 与其他模块关系
7. 变更记录

## 5. 链接规范

- 使用相对路径链接，避免仓库地址硬编码。
- PR 前必须检查文档链接是否失效。
- `用户手册.md` 和 `概要设计.md` 作为稳定入口，路径尽量不改。

## 6. 变更同步规范

- 修改 `src/core/*`：必须更新对应 `docs/模块/*`。
- 修改模式行为：必须更新 `docs/模式/*`。
- 修改协议或代理：必须更新 `docs/协议/*`。

## 7. 文风规范

- 默认中文，术语保留英文原词（如 `ReactFlow`、`WebSocket`）。
- 避免口语化草案描述和未决问题堆积。
- 行文先结论后细节，减少重复段落。

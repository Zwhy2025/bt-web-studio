# 调试模式

## 1. 目标与范围

- 目标：提供在线执行观测、断点控制与黑板检查能力。
- 范围：会话连接、执行控制、节点状态更新、断点与日志面板。
- 非目标：结构编辑（仅允许有限标注，不改树结构）。

## 2. 依赖与入口

- 布局容器：`src/components/layout/debug-layout.tsx`
- 画布：`src/components/layout/debug-canvas.tsx`
- 工具栏：`src/components/layout/debug-toolbar.tsx`
- 面板：`debug-logs-panel.tsx`、`breakpoint-panel.tsx`、`blackboard-panel.tsx`
- 调试通信：`src/core/debugger/real-websocket-client.ts`
- 调试状态：`src/core/store/debugModeState.ts`、`src/core/store/debuggerState.ts`

## 3. 核心概念

- 调试会话状态：`DISCONNECTED`、`CONNECTING`、`CONNECTED`、`ERROR`。
- 执行状态：`IDLE`、`RUNNING`、`PAUSED`、`STEPPING`。
- 断点模型：节点级断点、条件断点、命中统计。
- 事件源：后端推送状态、黑板和断点命中事件。

## 4. 关键流程

1. 用户连接调试会话。
2. 客户端请求初始树与当前状态。
3. 用户执行开始/暂停/单步/停止。
4. 节点状态与黑板面板实时更新。
5. 断点命中后进入暂停，用户解锁后继续。

## 5. 异常与边界

- 连接断开时保留最近一次状态快照并提示可重连。
- 消息解析失败时写入错误日志，不阻塞 UI 主线程。
- 高频状态刷新需要节流或批处理。
